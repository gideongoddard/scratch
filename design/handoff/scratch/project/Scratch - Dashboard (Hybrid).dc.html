How the Coach layer works · design intent for Claude Code

On every round saved, the derivation layer computes the metrics, then a snapshot of those numbers (with scope-correct deltas) is sent to Claude, which returns a structured insight — verdict, trend read, ranked focus areas — persisted per-round as round_insight and rendered above. Claude never computes a stat, and never asserts a cause the data doesn't hold.

FOUR GUARDRAILS AGAINST HALLUCINATION
1 · Facts in, narration out

Claude gets a pre-computed evidence packet — exact figures plus the blow-up list with each hole's recorded attributes — never raw rounds. It phrases facts; it can't compute or discover one.

2 · No cause without a computed link

“The driver caused this 8” is allowed only if the derivation layer joined teeClub + accuracy + penalty at that hole. No such data ⇒ the prompt forbids the claim.

3 · Cite & validate

Each insight carries the metrics it rests on; a deterministic check confirms every figure in the output exists in the packet, and regenerates if one doesn't reconcile.

4 · Knows what it can't see

An explicit “not tracked” list (bunkers, penalties, club…) is passed in, so the model defers on dimensions you don't capture instead of inventing one.

The card above is mocked copy in that exact shape — and an earlier draft of it fabricated “the 9 and the 8s came from the driver,” which these rules exist to catch.
