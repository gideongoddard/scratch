INVARIANT The 9-vs-18 rule

A 9-hole total is never placed beside an 18-hole total as if comparable. Every total carries a scope tag. Trends plot 9 and 18 on separate tracks (or compare to par-relative / per-hole figures, never raw gross). Compare is scope-locked — it will only pair like with like. This is wired into the components below, not left to the implementer's memory.

05 — METRIC DECISIONS · LOCKED

What we measure

Resolved. Four derivations go in for free, three new fields get added to the model, and three are out of scope. The two model changes are flagged for Claude Code below with concrete schema — note that historical rounds (your seed data) won't carry them, so every treatment must degrade gracefully to “not tracked”.

✓ CONFIRMED — all four going in · derive from existing fields, no schema change
Scrambling %Par-or-better on holes you missed the green = !gir && scoreVsPar ≤ 0. Directly addresses short-game recovery. Recommend adding to derivations.
Score distributionBirdie / par / bogey / double / triple+ counts from scoreVsPar buckets. Powers the score-mix bar.
Miss directionLeft / right tendency off the tee from accuracy on par-4/5s. A two-sided bias chart.
Putts on GIR vs missSplits putting from approach noise. Possible from putts + gir, but tiny samples — label as low-confidence.
+ APPROVED MODEL CHANGES — for Claude Code · new fields, nullable so seed rounds stay valid
Penalties
Per-hole penalty strokes — lets a 10 or 9 be attributed instead of guessed at. Surfaces as a penalties stat + a flag on the score-to-par strip.
HoleScore.penalties: number // default 0; new derivation totalPenalties()
Accuracy granularity
Two new miss values beyond left/right. Upgrades the bias chart to a full miss-dispersion (left · right · long · short). Optional value so existing rounds keep hit/left/right.
Accuracy = "hit" | "left" | "right" | "long" | "short"
↳ confirm the exact enum — open to a separate tee/approach split if you'd rather track both phases
Club off the tee
The club hit on each tee shot. Without it, accuracy swings can't be attributed to a club change — the dashboard can show fairways fell 86%→64%, but not that the driver caused it. Your tracking app captures this; it isn't in the seed rounds. Once stored, the Coach can tie the accuracy/distance trade-off to specific clubs.
HoleScore.teeClub?: string | null // nullable; absent on historical rounds
↳ to wire up with Claude Code — confirm whether it's a free enum or a fixed club list
✕ OUT OF SCOPE — not building; revisit later if needed
Lag puttingNeeds first-putt distance; putt count can't isolate it. 3-putt count remains the only proxy and is labelled as such.
Greenside bunkersNo sand / up-and-down capture. Penalties + scrambling % will partially illuminate short-game cost instead.
Strokes gainedRequires an expected-strokes baseline dataset that doesn't exist in the model. Shelved.
